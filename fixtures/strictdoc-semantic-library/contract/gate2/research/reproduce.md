# Reproduction and publication boundary

All experiments are private Gate 2 capability probes. They do not install a
production semantic engine, mutate the Scribe consumer, or write Git history.
Dependencies/source downloads remain under private outputs and must not enter a
review diff.

## Executed environment

Linux x86_64; CPython 3.13.15 virtual environment; rustworkx 0.18.1, NetworkX
3.6.1, Cozo embedded 0.7.6, NumPy 2.5.3; OPA 1.20.2 official static binary; Bun
1.4.2; OPA Wasm npm SDK 1.10.0. StrictDoc uses its separate pinned Nix Python
3.14 environment and reports 0.28.3. The existing effect-tui addon is host-local
at the recorded revision, not built by this workflow.

The source/wheel/npm probes do not establish a future devenv closure, supported
operating systems, CPython 3.14 wheel compatibility, cross-platform native addon
builds, cancellation, asynchronous execution or incremental behavior. Those are
explicit later entry checks. The source inspection of pinned nixpkgs is recorded
separately; this consumer's eventual package selection may use a different
supplied `pkgs`.

## Replay from a published or frozen packet

Evidence correction v2 fixes the v1 producer-layout instructions. The published
`research` directory is an immutable input packet, not an installation/work
directory. First copy its experiment files into disposable scratch. Set `packet`
to the directory containing this `reproduce.md`; for the evidence-review layout
it is `inputs/research`.

```bash
packet="$PWD/inputs/research"
scratch=$(mktemp -d -t strictdoc-gate2-replay.XXXXXXXX)
cp -a "$packet/experiments" "$scratch/experiments"
bash "$scratch/experiments/scripts/setup.sh"
bash "$scratch/experiments/scripts/run.sh" --backends
```

The copy precedes setup or run: both scripts write relative to their own
location. Never run them directly inside the frozen packet. `setup.sh` creates
its Python install/cache/venv and npm dependencies in the copied experiment
directory. It requires existing `uv`, `python3`, Bun and network access, and is
Linux amd64 specific because of the pinned OPA binary. It does not install
StrictDoc or build the effect-tui addon. Setup is reconstructed from the
executed acquisition commands and syntax-checked; v2 replay used existing
private dependencies without a new setup/network/build sweep.

`run.sh --backends` runs Rego validation, the three finalist backends, provider
status controls, the bounded Cozo lock probe, Bun Wasm compilation/evaluation
and cost probes. It requires no `inputs/toolchain`, StrictDoc Nix output or
effect-tui checkout. Neutral Parent and Child JSON inputs are regenerated by
`finalists.py`.

## Meaningful controls

- `native_probe.py`: native Parent-only/Child-only/mixed named versus
  absent-role cycles, self-loop, missing target, bridge, multiple roots/parents;
  verifies source bytes unchanged by export.
- `native_scope_probe.py`: existing native cycle detector with default versus
  explicit all-role selection; no upstream code patch.
- `finalists.py` plus `policy.rego`/`traversal.cozo`: independently normalized
  path oracle and literal Parent/Child truth rows; selector contexts, nonlocal
  boundary/move changes, nested origin, Child ownership/cycle, snapshots, Cozo
  abort/commit/custom rule/error.
- `opa-bun.cjs`: same Rego compiled to Wasm and executed under Bun; Parent and
  Child hierarchies, open/closed updates, and unchanged/changed records under
  the same nonempty baseline.
- `providers.py`: complete empty and protected results versus process, timeout,
  parse, completeness and identity failures. Harness contract, not authenticated
  identity or an adopted provider API.
- `cozo_lock_probe.py`: isolated worker is killed after a bounded wait on a read
  behind an active memory-engine writer. It is deliberately expected to hit the
  deadline.
- `cost_probe.py`: three serial full evaluations plus deep-boundary control,
  1,000/10,000 nodes, wide/deep; eight-second worker budget. It is not a
  production benchmark or incremental measurement.
- `interop.sh`: existing N-API/PyO3/Python health route and invalid-operation
  propagation under Bun.

`opa-default-error.json` and `opa-strict-error.json` additionally record
`opa eval --format=json '1 / 0'` with and without `--strict-builtin-errors`. The
former is undefined; the latter is an explicit error. A real adapter must not
treat either missing expected decision or acquisition failure as policy success.

## Small publication allowlist

`publication-allowlist.json` is the exact list of reviewable authored
documentation/scripts/inputs/results. It includes the reconstructed
setup/runner, small native inputs, query artifacts, raw results, selected useful
logs, and Bun dependency pin/lock. It excludes all downloaded upstream source
trees, source archives, native binaries, virtual environments, package caches,
node_modules, generated exports, bytecode, and transient build output.

The allowlist is a review aid, not authorization to publish. No commits, pushes,
external issue reports, deployments or adoption occurred. The coordinator may
copy only that allowlist into a human-review packet after both independent
designs are frozen.
