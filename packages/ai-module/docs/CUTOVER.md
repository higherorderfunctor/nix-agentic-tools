# ai-module: switching callers to the layers (PR 3)

Plan only; no code changes in this chunk. It moves every in-scope caller onto
the PR 2 layers in [DESIGN.md](DESIGN.md), deletes what they supersede, then
drops the `2` suffixes. Row IDs refer to `private/files-redesign/ledger.md` (223
rows); `G<n>`/`F<n>` refer to `private/files-redesign/gaps.md`. Those private
files are review evidence, not dependencies. Operator decisions in
`private/files-redesign/PLAN.md` are settled and not reopened here.

Notation: `R` = `ai.<owner>.files2` (layer 1), `F` = `ai.files2` (layer 2), `A`
= `ai.activation2` (layer 3), `S` = the new producer staging option
`ai.<runtime>._generatedFiles` (section 1.4). "Old path" = `lib/ai/adapters` →
`lib/ai/deliver.nix` → `lib/ai/own.nix`/`own.py`. Table 1.1 shows final names;
the rest uses the interim `2` names that chunk 14 drops (section 5).

### 1.2 Layer-1 helper: what PR 3 adds to `runtimeModule`

`runtimeModule { name; enabled; shared ? []; }`, still one file
(`packages/ai-module/lib/runtime.nix`). Every repository module that reaches HM
or devenv through ai-module imports one instance with its owner name.

| Addition                            | Behavior                                                                                                                                                                                 | Why                                                                                                                                                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `_file = toString ./runtime.nix`    | Attributes every forwarded definition to the helper instead of the importing owner module                                                                                                | The root-option guard (section 3.1) exempts exactly this file; without it the definitions report the importer (measured, Evidence E1/E2)                                                                                |
| `ai.<name>.activation2`             | `attrsOf` activation entry; forwarded with `mkAliasAndWrapDefsWithPriority lib.id` **outside** the `enabled` gate, plus one `enable = lib.mkDefault enabled` definition per declared key | Retirement and daemon release entries (`runWhenDisabled`) must run while the owner is disabled; the per-key default makes "ordinary commands stop when the owner is disabled" structural instead of a per-producer duty |
| `ai.<name>.legacyLedgers`           | Internal `listOf { codec = enum ["dir" "json"]; ledger = str; path = str; }`, forwarded unconditionally into internal root `ai.legacyLedgers` (declared in `modules/common.nix`)         | Section 2: a disabled owner must still drain what its old writer owned                                                                                                                                                  |
| `imports = [../modules/common.nix]` | Declares the root options it forwards into; a path import, so it deduplicates with the backend modules' own                                                                              | A runtime factory evaluated without the backend modules (`checks/ai-factory`)                                                                                                                                           |
| `shared` (list of paths)            | Keys in `shared` are forwarded but not recorded in `ai.files2Owners`                                                                                                                     | Shared `AGENTS.md`: the composer is the single claimant; agreeing or overriding runtime definitions merge by module priority (L037, L040, L069-L071; G12)                                                               |

The `shared` argument may depend on `config`: an import whose argument is a lazy
config thunk evaluates without recursion (Evidence E3).

## 3. Repo guards

### 3.1 Root `ai.*` definitions (`checks/module-provenance/helpers.nix`)

The guard flags any repo-file definition of a root `ai.*` option outside its
declaring file (`helpers.nix:104-127`). The forwarded definitions would be
attributed to the importing owner module without `_file` (E1), and to the helper
with it (E2). Change, in `rootPoolViolations`:

```nix
# Layer-1 forwarding is the one sanctioned root write: the ai-module helper
# re-publishes ai.<owner>.{files2,activation2,legacyLedgers} at the root and
# records claims in ai.files2Owners. It sets `_file`, so only it matches.
forwardingHelper = toString ../../packages/ai-module/lib/runtime.nix;
forwardedOptions = ["activation2" "files2" "files2Owners" "legacyLedgers"];
foreign = d:
  isOurs d.file
  && !(lib.elem (toString d.file) declaredIn)
  && !(lib.elem name forwardedOptions && toString d.file == forwardingHelper);
```

(`name` is the root option name `foreignDefs` already binds.) Fixtures in
`checks/module-provenance`: a synthetic owner forwarding through the helper
passes; a repo fixture module defining `ai.files2` directly, and one defining
`ai.activation2` directly, are still reported; the helper defining a root option
outside the list is reported. The comment block above the guard gains one
