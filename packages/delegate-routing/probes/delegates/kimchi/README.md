# Kimchi delegate replays

Pins, evidence marks and case-prefix meanings:
[evidence guide](../../../docs/delegates/evidence.md).

Every script runs the repository's pinned `kimchi` and `kimchi-workflows` (built
on demand; `KIMCHI_PKG` / `KIMCHI_WORKFLOWS_PKG` skip the build) and reads the
pinned sources (`kimchi.src`, `kimchi.extractionSources.pi`,
`kimchi-workflows.src`). Scratch output goes to `$PROBE_OUT/<name>` when set,
otherwise to a fresh temp dir that the script prints.

All cases are **OFFLINE**: a fresh HOME/XDG tree, a fake API key and a fake
gateway (`live/fakeprov.py`) on 127.0.0.1; `OLLAMA_HOST` points at a dead port.
One exception to "no network": `/workflow run` (the `w*` scenarios) lets
kimchi-workflows provision `.kimchi/workflows/` with pnpm, which may reach the
npm registry. No model provider is contacted, except by the two LIVE cases
(`claude:sp-p20-live-wire`, `claude:l1-live-agent-model-effort`), which run only
when named and go through `live/recproxy.py` to the real gateway with the apiKey
leaf of the operator's `~/.config/kimchi/config.json`.

## Harness

| File                              | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `live/drive.py <sc.json> [<out>]` | Builds the isolated HOME and `config.json` (`llmEndpoint` = fake), optional workflows link, project files; runs the pinned binary; feeds timed RPC/ACP stdin lines; auto-allows ACP permission requests; `full_wire` writes every request body to `wire.jsonl`; `pre_args` runs setup invocations (e.g. `memory-import`); `setup_sh` runs a strict-mode fixture shell first (e.g. a disposable repo whose linked worktree is the project); `tty` runs the TUI under a pseudo-terminal with raw keystroke `stdin_lines`; `config` adds non-secret `config.json` keys (TUI onboarding state); `@PROJ@` is substituted in argv, stdin lines and file text; `live_upstream` swaps in `recproxy.py` and scrubs the key files afterwards; cancellation fixtures wait for the active step provider request and log sends in `stdin.jsonl`. |
| `live/fakeprov.py`                | Fake gateway: `/v1/models/metadata` (fake-a, fake-b) and `/openai/v1/chat/completions` (SSE). A request offering `Agent` is the parent and follows the first `PLAN=…` user message; `.../embeddings` answers a constant unit vector; `NONREASONING=<slugs>` advertises reasoning=false; others are children (`SLEEP=n`, `CHILDPLAN=…`, `WFSLEEP=n`). Logs `provider.jsonl`.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `live/summ.py <out>`              | Wire summary: role, model, `reasoning_effort`, delegate tools, markers; LIVE `RESP` lines (model/effort sent, model returned, reasoning tokens); ACP `acp` lines (responses, `agent_message_chunk` text).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `live/all.sh [<name>…]`           | Runs every OFFLINE (or the named) scenario and writes `summary.txt` beside each; LIVE scenarios run only when named.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `live/prompt_map.py [<case>…]`    | System-prompt map (`claude:sp-*`): writes each case's scenario, runs `drive.py` with `full_wire`, renders `prompt-map.txt` with `sysprompt.py`, checks the case's expectations, prints PASS/FAIL (non-zero exit on FAIL). Default = every OFFLINE case; `--list` names them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `live/sysprompt.py <out>`         | One line per wire request: kind (main, child-replace, child-append, title, compaction, other), model, system role and size, message roles, and where every `SP_*` sentinel sits (system % offset under its heading, or user message index).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `live/prompt_map_ext.ts`          | User extension the prompt map installs: appends `SP_EXT_BAS` (before_agent_start) and `SP_EXT_BPR` (before_provider_request); logs execPath, wrapper env and the virtual module's block exports to `$HOME/spx-load.jsonl`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `live/recproxy.py`                | LIVE pass-through to `$UPSTREAM`: logs chat bodies to `wire.jsonl`, the metadata as slug + reasoning, and one `RESP` usage record per chat response (models named by the SSE chunks, final `usage`); headers are forwarded, never logged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `inv/run.sh <label> [args]`       | Tool inventory: `observer.ts` prints every registered tool and command at the first input event and swallows it (no model call).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `codex-side/offline.py <case>`    | Codex-side scripted-gateway cases.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `codex-side/node.sh <script.cjs>` | Runs a Codex-side TypeScript-AST/VM script with `TYPESCRIPT_JS`, `KIMCHI_SRC`, `PI_SRC`, `KIMCHI_WORKFLOWS_SRC` set; output JSON goes to the current directory.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
