# Codex delegate replays

Pins, evidence marks and case-prefix meanings:
[evidence guide](../../../docs/delegates/evidence.md).

Every script runs the repository's pinned `chatgpt-codex` with `--no-daemon`
(built on demand; `CODEX_PKG=<store path>` skips the build) and reads the pinned
source (`chatgpt-codex.src`). Scratch output goes to `$PROBE_OUT/<name>` when
set, otherwise to a fresh temp dir that the script prints. All cases are
**OFFLINE**: a scripted Responses provider on 127.0.0.1, a fake key, a fresh
`CODEX_HOME`. No account, no quota. One exception to `--no-daemon`: the
`tui-daemon` surface of `tui/tuiwire.sh` and every `daemonlife.sh` case start a
shared daemon inside their scratch home and stop it afterwards. Exceptions to
OFFLINE: `liveparity.sh` and `liveguardian.sh` spend one short turn each on the
operator's ChatGPT login, and the app-server's plugin manager may request
`chatgpt.com/backend-api/plugins/featured` at startup (401 with the fake key; no
model traffic).

The model catalog comes from `mkcache.py`, which wraps the catalog bundled in
the pinned source (`codex-rs/models-manager/models.json`). Its identity is
empty; no account cache or login is read. Catalog-dependent results describe
this bundled catalog. `codex:L3.live-parity` found the live account catalog's
`multi_agent_version` equal to it for every model both list (2026-10-07).

Set `PROBE_OUT` for the inventory + `inspect_ast.py` steps so both AST files
land in the same directory.

## Harness

| File                                           | Role                                                                                                                                                                                   |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run.sh <probe> [port]`                        | Builds `CODEX_HOME` from `probes/<probe>/`, runs `fp.py` and `asclient.py`, writes `<work>/results/<probe>/{wire,as,home}`. Set `CODEX_WORK` to reuse one work dir.                    |
| `fp.py`                                        | Fake provider; scripts tool calls per agent path (`/root`, `/root/a`, V1 children); logs every request and `log.jsonl`.                                                                |
| `asclient.py`                                  | Drives `codex app-server` over stdio: timed host actions, approval answers, `$THREAD/$TURN/$CHILD` substitution.                                                                       |
| `summ.py <results/probe>`                      | Wire summary plus the non-noise app-server events.                                                                                                                                     |
| `toggles.sh [variants]`, `toggles_report.py`   | One request per config variant; prints the multi-agent tool surface.                                                                                                                   |
| `offline.py`, `protocol.py`                    | Codex-side `codex exec` and app-server protocol cases.                                                                                                                                 |
| `inventory.py`, `sdk_ast.py`, `inspect_ast.py` | Codex-side CLI/schema inventory and tree-sitter AST of the pinned source.                                                                                                              |
| `sysprompt/wire.sh`                            | Captures system-prompt wire runs at the pin.                                                                                                                                           |
| `sentinels.py`, `basediff.py`                  | Where each sentinel lands per captured request; vendor-base hash and diff per request.                                                                                                 |
| `memories.sh [port] [probe]`                   | Two sessions in one home; backdates the first so the memory startup pipeline runs Phase 1 and Phase 2.                                                                                 |
| `tui/tuiwire.sh`, `tui/parity.py`              | TUI under tmux (embedded and shared daemon) beside app-server and exec; masked item-by-item request diff.                                                                              |
| `execlife.sh <probe> <port> [SIG delay]`       | `codex exec --json` on a probe; optional signal to the exec PID; exit code, aborted provider streams, surviving child shell processes.                                                 |
| `daemonlife.sh <probe> <port>`                 | Shared daemon in a scratch home; runs the probe's `phases.txt` (`client`, `queue`, `server`, `tui`, `tui-embedded`, `tui-remote`, `sleep`) and prints the provider requests.           |
| `wsuds.py <socket>`                            | stdio to WebSocket-over-unix-socket bridge: the daemon control socket is WebSocket, so `asclient.py` `"transport": "daemon"` attaches through it.                                      |
| `liveparity.sh [model]`                        | LIVE: account catalog vs bundled catalog per model, plus one real V2 spawn; scratch home holds a copy of `auth.json`, deleted on exit.                                                 |
| `liveguardian.sh [model]`, `liveproxy.py`      | LIVE: one app-server turn through a recording proxy (`openai_base_url`); logs request bodies and the catalog, never headers; scratch home with a copy of `auth.json`, deleted on exit. |
| `realtime.sh [port] [rtport]`, `rtws.py`       | Realtime startup over the websocket transport: `rtws.py` stands in for the Realtime endpoint and logs every client frame; empty scratch `HOME`.                                        |

`inventory.py` and `sdk_ast.py` need tree-sitter in a throwaway venv:

```bash
uv venv "$d/venv" && uv pip install --python "$d/venv/bin/python" tree-sitter==0.25.2 tree-sitter-rust==0.24.2 tree-sitter-typescript==0.23.2
```

### Prompt-map unknowns (managed text, hooks, side turns, TUI)

`sentinels.py <wire-dir> SENTINEL...` prints, per captured request, the input
item (role, first tag, index) that carries each sentinel; `-` means absent.
`basediff.py <wire-dir> [ref]` hashes each request's vendor base and diffs the
ones that differ. After a `run.sh`, `R=$PROBE_OUT/codex/results/<probe>`.

A probe's `etc-codex/` is mounted at `/etc/codex` by `run.sh` inside an
unprivileged `bwrap` namespace (tmp-overlay over `/etc`): no root, host `/etc`
untouched. Sentinels: `CFG-DEV-4000` config `developer_instructions`;
`REQ-ADI-4001` requirements `additional_developer_instructions`;
`HOOK-SESSSTART-4002`, `HOOK-UPS-4003`, `HOOK-SUBSTART-4004`,
`HOOK-POSTTOOL-4005` command-hook `additionalContext`; `GLOBAL-AGENTS-4006`
`$CODEX_HOME/AGENTS.md`.
`H6="CFG-DEV-4000 REQ-ADI-4001 HOOK-SESSSTART-4002 HOOK-UPS-4003 HOOK-SUBSTART-4004 HOOK-POSTTOOL-4005"`.

### Delegate lifecycle unknowns (exec, daemon, approvals, restart)

`R=$PROBE_OUT/codex/results/<probe>`. `fp.py` scripts an internal worker's
requests under its `x-openai-subagent` label (`guardian` for auto-review,
`review`, `memory_consolidation`) and the TUI title side turn as `title` when
the scenario has that key; a step's `stall` holds the stream silently, so the
client's `stream_idle_timeout_ms` trips. `asclient.py` `"approval": "none"`
never answers an approval; `"resume": "as/thread_id"` (with `"attach": false` to
observe only) and `"turn": null` drive later clients; `probe2.json` runs a
second app-server process on the same home.
