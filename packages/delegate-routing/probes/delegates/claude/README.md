# Claude Code delegate replays

Pins, evidence marks and case-prefix meanings:
[evidence guide](../../../docs/delegates/evidence.md).

Every script runs the repository's pinned `claude-code` (built on demand from
`.#ciPackages.<system>.claude-code`; set `CLAUDE_BIN=<path>/bin/claude` to skip
the build). Scratch output goes to `$PROBE_OUT/<name>` when `PROBE_OUT` is set,
otherwise to a fresh temp dir that the script prints. Nothing is written inside
the repository. `../common/pin.{py,sh}` hold the shared lookup.

- **OFFLINE** cases run against a scripted Anthropic Messages mock on 127.0.0.1
  with a fake key and an isolated `CLAUDE_CONFIG_DIR`. No account, no quota.
- **LIVE** cases use the operator's own Claude login and cost quota.

## Harness

| File                                                   | Role                                                                                                                                                                                                                                           |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `harness.py <case>...`                                 | Starts the mock, runs the pinned binary per case. Writes `out/<case>/{NNN.json,summary.json,stdout,stderr,debug.log,argv.json}` and prints one line per model request: role (main/child/wfchild), model, effort, tool count, the mock's reply. |
| `cases.py`                                             | One scripted mock behaviour per case (judge cases at the end).                                                                                                                                                                                 |
| `mkfixture.sh <dir>`                                   | Builds the throwaway git fixture with the named agents and saved workflow. `harness.py` calls it.                                                                                                                                              |
| `hook.sh`                                              | Logging hook used by the `hooks_*` cases.                                                                                                                                                                                                      |
| `unpack.sh <dir>`                                      | Unpacks the pinned binary's Bun module graph with `packages/claude-code/extract/bununpack.py`. Input to the grep and AST scripts.                                                                                                              |
| `sysprompt/capture.sh`                                 | Re-runs the system-prompt capture cases (`codex:P`) with `sysprompt/mock.py`; `sysprompt/an.py <case-dir>` shows where each sentinel token landed.                                                                                             |
| `host/`, `agent/`, `workflow/`, `capture_inventory.py` | The Codex-side replays (`codex:H`, `codex:A`, `codex:W`, `codex:C`).                                                                                                                                                                           |

The AST scripts need acorn on `NODE_PATH`; it is not in nixpkgs:

```bash
d=$(mktemp -d) && npm install --prefix "$d" acorn@8 && export NODE_PATH="$d/node_modules"
```

### Codex-side replays

```bash
u=$(./unpack.sh "$(mktemp -d)")              # bundle for the G/AST scripts
python3 agent/static_snippets.py "$u"        # codex:A, G evidence
node agent/verify_depth.js "$u"              # codex:A, resolver + gate in a VM
python3 host/mcp-replay.py                   # codex:H; prints runs/mcp-serve
python3 agent/extract_schemas.py <sysprompt-work> <run>/transcript.json   # codex:A schemas
```

`sysprompt/capture.sh` reconstructs the prior study's captures. Those runs
recorded argv only, so the plan, stdin and env per case are inferred from the
argv and the plan files' match tokens; `k8-compact` is not reproduced.
